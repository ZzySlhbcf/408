# 3.5.1 信道划分介质访问控制

复用: 在发送端把多个发送方的信号组合在一个物理信道上进行传输, 在接收端把收到的复用信号分离出来, 并发送给对应的接收方

## 时分复用(TDM)

时分复用(Time Divison Multiplexing, TDM)将信道的传输时间划分为一段段等长的时间片, 称为TDM帧, 每个用户在每个TDM帧中占用固定序号的时隙, 并且周期性的出现(周期为TDM的长度), 所有用户在不同时间占用同样的信道资源

>[!attention] TDM帧是一段固定长度的**时间**

![[时分复用的原理.png]]

从某个时刻来看, 时分复用信道上传送的仅是某对用户之间的信号; 从某段时间来看, 传送的是按时间分割的复用信号

因为时分复用是按固定次序给用户分配时隙的, 当用户在某段时间暂无数据传输时, 其他用户也无法使用这个暂时空闲的线路资源, 所以时分复用后的信道利用率不高

>[!info] 统计时分复用(StatiSticTDM, STDM)
>STDM帧与TDM帧不同, 并不固定分配时隙, 而按需动态分配时隙, 当用户有数据要传送时, 才会分配到STDM帧中的时隙, 因此可以提高线路的利用率例如
>假设线路的数据传输速率为6000b/s, 3个用户的平均速率都为2000b/s, 当采用TDM方式时, 每个用户的最高速率为2000b/s
>而在STDM方式下, 每个用户的最高速率可达6000b/s


## 频分复用(FDM)

将信道的总频带划分为多个子频带, 每个子频带作为一个子信道, 每对用户使用一个子信道进行通信. 所有用户在同
一时间占用不同的频带资源. 每个子信道分配的频带可不相同, 但它们的总和不能超过信道的总频带

在实际应用中, 为了防止子信道之间互相干扰, 相邻信道间还要加入"隔离频带"

![[频分复用的原理.png]]

充分利用了传输介质的带宽, 系统效率较高, 实现容易

## 波分复用(WDM)

(Wavelength Division Multiplexing, WDM)即光的频分复用, 在一根光纤中传输多种不同波长的光信号, 最后用光分用器将各路波长分解出来

## 码分复用(CDM)

码分复用(Code Division Multiplexing，CDM)是采用不同的编码来区分各路原始信号的一种复用方式
与FDM和TDM不同, 它既共享信道的频率, 又共享时间

实际上，更常用的名词是码分多址(Code Division Multiple Access，CDMA), 其原理是将每个比特时间再划分成m个短的时间槽, 称为码片(Chip), 通常m的值是64或128

每个站点被指派一个唯一的m位码片序列. 发送1时, 站点发送它的码片序列; 发送0时, 站点发送该码片序列的反码
当两个或多个站点同时发送时, 各路数据在信道中线性相加. 为了从信道中分离出各路信号, 要求各个站点的码片序列相互正交

简单理解就是, A站向C站发出的信号用一个向量来表示, B站向C站发出的信号用另一个向量来表示, 两个向量要求相互正交. 向量中的分量, 就是所谓的码片

令向量S表示A站的码片向量, T表示B站的码片向量
假设A站的码片序列被指派为00011011, 则A站发送00011011就表示发送比特1, 发送11100100就表示发送比特0
为了方便计算, 将码片中的0写为-1, 将1写为+1, 因此A站的码片序列是(-1-1-1+1+1-1+1+1)
不同站的码片序列相互正交，即向量S和T的规格化内积为0
$$S\cdot T=\frac{1}{m}\sum^{m}_{i=1}S_{i}T_{i}=0$$
任何站的码片向量和该码片向量自身的规格化内积都是1: 
$$S\cdot{S}=\frac{1}{m}\sum^{m}_{i=1}S_{i}^2=1$$
任何站的码片向量和该码片反码的向量的规格化内积都是-1:
$$S\cdot\overline{S}=\frac{1}{m}\sum^{m}_{i=1}S_{i}\overline{S}_{i}=-\frac{1}{m}\sum^{m}_{i=1}S^2_{i}=-1$$
令向量T为(-1-1+1-1+1+1+1-1)
当A站向C站发送数据1时, 就发送了向量(-1-1-1+1+1-1+1+1)
当B站向C站发送数据0时, 就发送了向量（+1+1-1+1-1-1-1+1)
两个向量在公共信道上叠加，实际上是线性相加，得到
$$S+\overline{T}=(\begin{matrix}
0&0&-2&2&0&-2&0&2
\end{matrix})$$
到达C站后, 进行数据分离, 若要得到来自A站的数据, 则C站就必须知道A站的码片序列, 让S与$S+\overline{T}$进行规格化内积
根据叠加原理, 其他站点的信号都在内积的结果中被过滤掉
内积的相关项都是0, 而只剩下A站发送的信号, 得到
$$S\cdot(S+\overline{T})=1$$
所以A站发出的数据是1. 同理，若要得到来自B站的数据, 则
$$T\cdot(S+\overline{T})=-1$$
因此从B站发送过来的信号向量是一个反码向量, 代表0

# 3.5.2 随机访问介质访问控制

在随机访问协议中, 所有用户都能根据自己的意愿随机地发送信息, 占用信道的全部速率, 在总线形网络中, 当有两个或多个用户同时发送信息时, 就会产生帧冲突(也称碰撞), 导致所有冲突用户的发送均以失败告终

为了解决随机访问发生的冲突, 每个用户需要按照一定的规则反复地重传它的帧, 直到该帧无冲突地通过, 这些规则就是随机访问介质访问控制协议，其核心思想是: **胜利者通过争用获得信道进而获得信息的发送权**. 因此, 随机访问介质访问控制协议也称**争用型协议**

若采用信道划分机制, 则节点之间的通信要么共享空间, 要么共享时间, 要么共享空间和时间; 而若采用随机访问控制机制, 则节点之间的通信既不共享时间, 又不共享空间
随机介质访问控制实质上是一种**将广播信道转换为点到点信道的机制**

## ALOHA协议

### 纯ALOHA协议

当总线形网络中的任何站点需要发送数据时, 可以不进行任何检测就发送数据. 若在一段时间内未收到确认, 则该站点就认为传输过程中发生了冲突, 发送站点需要等待一段随机的时间后再发送数据, 直至发送成功

![[纯ALOHA协议.png]]

### 时隙ALOHA协议

将时间划分为等长的间隙, 并规定:
1. 主机只有在每个间隙开始的时刻才能发送帧
2. 发送一帧的时间必须小于等于时隙的长度
时隙ALOHA协议冲突后采取的重发策略与纯ALOHA协议类似

![[时隙ALOHA协议.png]]

## CSMA协议

CSMA(载波多路访问)协议的主要思想是主机在发送前检测信道是否被占用, 仅当未被占用才能发送数据

1. 1-坚持CSMA
   + 经监听, 如果信道空闲, 立刻发送数据
   + 如果信道忙, 则继续监听信道, 重复上步
1. 非坚持CSMA
   + 经监听, 如果信道空闲, 立刻发送数据
   + 如果信道忙, 则随机等待一个时间段后, 再开始监听, 重复上步
1. p-坚持CSMA
   + 经监听, 如果信道空闲, 则以p的概率立即发送数据, 以1-p的概率推迟到下一个时隙重复步骤
   + 如果信道忙, 则下一个时隙重新监听, 一旦空闲重复步骤

|          | 优点                    | 缺点                               |
| -------- | --------------------- | -------------------------------- |
| 1-坚持CSMA | 空闲时发送数据的延迟时间很短        | 多个主机可能同时发送数据导致冲突的可能性也较大          |
| 非坚持CSMA  | 降低了多台主机同时发送数据导致冲突的可能性 | 不能及时捕捉信道变为空闲, 可能增加等待时延, 同时浪费信道资源 |
| p-坚持CSMA | 降低了多台主机同时发送数据导致冲突的可能性 | 可能因为屡次判定失败而导致信道空闲却无法发送数据         |

## CSMA/CD协议

### CSMA/CD协议的工作过程

在CSMA协议的基础上加入了碰撞检测机制(Collision Detection)

>载波监听: 是指每个站点在发送前和发送过程中都必须不停地检测信道, 在发送前检测信道是为了获得发送权, 在发送过程中检测是为了及时发现发送地数据是否冲突
>冲突检测: 网络适配器边发送数据边检测信道上电压的变化情况, 如果有多个主机同时发送数据, 总线上信号的电压变化幅度将会变大, 主机通过信号的电压变化幅度来检测冲突

>[!info] 适用于半双工网络或总线型网络

![[传播时延对载波监听的影响.png]]

1. 适配器将需要发送的数据封装成帧, 准备发送
2. 适配器对信道进行监听, 如果信道忙, 则持续监听直到信道空闲, 然后开始发送该帧
3. 在发送的过程中, 适配器持续监听信道, 进行碰撞检测
4. 因检测到碰撞而中止发送后, 适配器执行二进制指数退避算法, 等待随机时间后返回2

>[!note] 先听后发, 边听边发, 冲突停发, 随机重发

### 最小帧长与争用期

在共享式以太网中，端到端**传播时延**的2倍$2\tau$被称为**争用期**, 即主机从发送帧开始, 最多经过时长$2\tau$就可检测出所发送的帧是否遭受碰撞为了确保共享总线上的每一台主机在发送完一个完整的帧之前, 能够检测出是否产生了碰撞, 发送的数据帧的长度必须大于一个特定的值, 这个特定的值就被称为**最小帧长**
$$最小帧长=争用期\times数据传输速率$$
对于10Mb/s的共享总线以太网, 其争用期$2\tau$的值规定为51.2μs, 因此其最小帧长为512b, 即64B

### 截断二进制指数退避算法

当主机检测到碰撞时, 需停止发送, 并等待一段时间后进行重传. 在以太网中, 使用截断二进制指数退避算法来确定碰撞后重传的时机

1. 确定基本退避时间, 取2倍总线端到端的传播时延$2\tau$(争用期)
2. 若当前已经重传的次数为n, 设变量k=n+1(k表示正在进行第k次重传), 若k>10, 则令k=10
3. 从整数集合$\{0,1,\cdots,(2^k-1)\}$中随机取出一个数, 记错r
4. 随机退避的时间为$t=r\times{2}\tau$, 即r倍的基本退避时间
5. 如果该数据帧又发生碰撞, 则返回步骤1重新计算推迟时间

>[!note] 如果重传了16次仍未成功, 那么丢弃数据并向上层报告

## CSMA/CA协议

>[!info] 无线局域网无法使用冲突检测的原因
>1. 适配器接收到的信号强渡远小于发送信号强渡, 且在无线介质上信号强渡的动态变化范围很大
>2. 在无线通信中, 并非所有站点都能听见对方, 存在"隐藏站"

将CA改为冲突避免(Collision Avoidance, CA)

无线信道的通信质量远不如有线信道, 802.11标准使用链路层确认/重传(ARQ)方案, 即站点每通过无线局域网发送完一帧, 就要在收到对方的确认帧后才能继续发送下一帧
>[!info] 802.11标准无线局域网采用的停止-等待协议是一种可靠传输协议

### 帧间间隔

检测到信道空闲后, 还要等待一段很短的时间(继续监听)才能发送帧, 这段时间称为帧间间隔(InterFrame Space,IFS)

![[IFS.png]]

1. 短帧间间隔(SIFS): 最短的帧间间隔, 长度未28us, 用于分割一次对话的各帧, 如ACK帧、CTSz帧以及分片得到的多个数据帧等
2. 点调节功能帧间间隔(PIFS): 长度介于SIFS和DIFS, 在点协调功能PCF操作中使用
3. 分布调节功能帧间间隔(DIFS): 长度为128us, 在分布协调功能DCF方式中, DIFS用于发送数据帧和管理帧

### 虚拟载波监听

虚拟载波监听指的是发送方A在向接收方B发送数据帧DATA时, 会同时通知其他站点自己需要占用信道的总时间, 其他站点根据该时间创建自己的网络分配向量NAV
NAV指出了信道忙的持续时间, 这段时间内A和B以外的站点都不能在这段时间发送数据

>[!note] 总时间
>发送数据帧DATA的时间+SIFS+发送确认帧ACK的时间, 该值记录在数据帧的首部

### 争用期和退避思想

CSMA/CA协议规定, 所有推迟接入的站, 都必须在争用期执行统一的退避算法开始公平地争用信道
争用期也叫争用窗口CW, 争用窗口由许多时隙组成

![[基于争用期地信道争用.png]]

>[!info] 退避算法
>1. 站点在进入争用期时, 应在0~CW个时隙中随机生成一个退避时隙数并设置退避计时器
>   例如, 站点C的退避时隙数为3, 而站点D的退避时隙数为9
>2. 当几个站同时争用信道时, 计时器最先降为零的站首先接入媒体, 发送数据帧
>   这时信道转为忙, 而其他正在退避的站则冻结其计时器, 保留计时器的数值不变, 推迟到在下次争用信道时接着倒计时
>3. 若未收到确认帧, 则需要重传, 每重传一次, 争用窗口的数值就近似加倍增大, 在进行重传时，第i次重传的争用窗口$CW=2^{4+i}-1$
>   当随机退避的时隙数在0~1023之间生成时(即i=6时)，争用窗口CW便不再增大
>   首次争用信道时(即i=0时）, 随机退避时隙数应在0~15之间生成

争用期并不是每次发送数据都需要的，发送数据必须经过争用期进行公平竞争的几种情况:
1. 要发送使数据时检测到信道忙
2. 已发送地数据帧未收到确认, 重传数据帧
3. 接着发送后续地数据帧

### 信道预约

为了解决隐蔽站地问题, 无线局域网标准IEEE802.11允许发送方对信道进行预约, 预约依靠两种控制帧
1. RTS帧: 包括源地址、目的地址、本次通信所需地持续时间
2. CTS帧: 包括本次通信所需地持续时间

在A站发送数据之前, 必须先给B发送一个RTS帧, 随后B给A发送一个CTS帧, 表示同意接收数据

# 3.5.3 轮询访问: 令牌传递协议

轮询访问介质访问控制是指按一定的次序轮流询问链路中的各个主机, 被询问到的主机才能进行数据传输, 未被询问的主机必须等待, 令牌传递协议就是一种典型的轮询访问协议
## 令牌传递协议(用于令牌环网）

令牌传递协议中一个特殊的数据帧作为令牌不停地在环中流动, 只有获得了令牌的主机才能发送数据, 因此不存在冲突. 令牌传递协议适用于负载较大的链路

## 令牌传递协议的工作过程

1. 当网络空闲时, 环路中只有令牌帧在循环传递 
2. 当令牌传递到有数据要发送的站点时, 就在令牌中附加自己需要传输的数据, 将令牌变成一个数据帧, 然后发送出去
3. 数据帧沿着环路传输, 接收到的站点一边转发数据, 一边查看帧的目的地址
   若目的地址和自己的地址相同, 则接收站就复制该数据帧, 以便进一步处理
4. 数据帧沿着环路传输, 直到到达该帧的源站点, 源站点收到自己发出去的帧后便不再转发
   同时, 通过检验返回的帧来查看数据传输过程中是否出错, 若出错则重传
5. 源站点传送完数据后, 重新产生一个令牌, 并传递给下一站点, 交出信道控制权

>[!attention] 令牌传递协议只涉及到了主机之间的令牌传递, 所以其物理拓扑可以不是环形网, 但其逻辑拓扑必须是环形网
