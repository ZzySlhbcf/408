# 1.2.1 计算机网络分层结构


+ 协议数据单元(PDU): 对等层之间的数据单位, 第n层称为n-PDU, 分为SDU和PCL两部分
+ 服务数据单元(SDU): 层与层之间交换的数据单位, 第n层称为n-SDU
+ 协议控制信息(PCL): 控制协议操作的信息, 第n层称为n-PCL

n-SDU+n-PCL=n-PDU=(n-1)-SDU: 将第n+1层收到的PDU作为第n层的SDU, 加上第n层的PCL, 封装成第n层PDU, 交给第n-1层后作为SDU

>[!note] 
>1. 可以将多个SDU合并成一个PDU (多个应用层报文合并成一个UDP段)
>2. 将一个SDU划分为几个PDU (IP分片)

1. 第n层的实体不仅要作为第n-1层的服务来实现自身定义的功能, 还要向第n+1层提供本层的服务, 该服务是第n层及其下面各层提供的服务总和
2. 最低层只提供, 是整个层次结构的基础; 最高层面向用户提供服务
3. 上一层只能通过相邻层间的接口使用下一层的服务, 而不能调用其他层的服务
4. 通信时, 对等层在逻辑上有一个直接通信, 表现为能直接将信息传送到对方

# 1.2.2 计算机网络协议、接口、服务的概念

1. 协议: 控制在**对等实体**之间进行通信的规则的集合, 协议是"水平的"
   + 语法: **数据与控制信息的格式或结构**
   + 语义: 即**需要发出何种控制信息、完成何种动作及做出何种应答**
   + 同步(或时序): 执行各种操作的条件、时序关系等, 即**时间实现顺序的详细说明**
1. 接口: 同一节点内相邻两层的实体交换信息的逻辑接口, 只有在相邻的层之间才能定义接口
2. 服务: 下层为紧邻的上层提供的功能调用, 功能是"垂直的", 并非在一层内完成的全部功能能称为服务, 只有被高一层实体"看得见"的功能才称为服务

![[协议、接口、服务三者之间的关系.png]]

1. 面向连接和无连接服务
   + 面向连接: 通信双方必须先建立连接, TCP
   + 无连接(尽最大努力交付): 不需要先建立连接, IP、UDP
1. 可靠和不可靠服务
   + 可靠服务: 具有纠错、检错和应答机制
   + 不可靠服务: 尽量让数据正确、可靠的地传送到目的地
1. 有应答和无应答服务
   + 有应答: 由传输系统内部自动实现, 文件传输服务
   + 无应答: 接收方不自动给出应答, 若需要应答, 则由高层实现

# 1.2.3 ISO/OSI参考模型和TCP/IP模型

## OSI参考模型

![[ISO参考模型.png]]

1. [[2.1 通信基础|物理层]]: 传输单位是**比特**, 透明地在物理介质上为数据设备透明地传输原始比特流
   + 通信链路与通信节点地连接需要的一些电路接口, 物理层规定了这些接口的参数
   + 规定了链路上所传输信号的意义和电气特性
   + 传输介质(双绞线)不在物理层协议之内, 而在物理层协议下面
1. [[3.1 数据链路层的功能|数据链路层]]: 传输单位是**帧**, 加强物理层传输原始比特流的功能
   + 将物理层提供的物理连接转化为数据链路
   + 将网络层交来的IP分组封装成帧, 传输到相邻节点的网络层, 实现节点之间的**差错控制和流量控制**
1. [[4.1 网络层的功能|网络层]]: 传输单位是**数据报**, 通信子网的运行控制
   + 将网络层的协议数据单元(分组)从源主机传输到目的主机, 为分组交换网上的不同主机提供通信服务
   + 路由选择、流量控制、拥塞控制、差错控制和网际互连
   + 虚电路服务和数据报服务
1. 传输层(会话层): 为表示层实体或用户进程建立连接, 这就是**会话**, 建立同步(SYN), 负责管理主机间的会话进程
   + 建立、管理和终止进程间的会话
   + 通过**检查点机制**维持可靠会话, 通信失效时从检查点继续恢复通话
1. 表示层: 处理在不同主机中交换信息的表示方式(编码和表示不同)
   + 数据压缩、加密、解密
1. 应用层: 用户与网络的接口, 使用的协议最多

## TCP/IP模型

![[TCPIP模型.png]]

1. 网络接口层: 物理层+数据链路层
   + TCP/IP描述网络接口层的功能和协议, 只是指出主机必须使用某种协议与网络连接
1. 网际层(主机-主机): 网络层, 无连接不可靠的数据报服务
2. 传输层(应用-应用或进程-进程): 传输层, 发送端和目的端主机上的对等实体进行会话
   + 传输控制协议(TCP): 面向连接, 数据传输的单位是报文段
   + 用户数据报协议(UDP): 无连接, 数据传输的单位是用户数据报
1. 应用层(用户-用户): 包含所有高层协议: 虚拟终端协议Telnet、文件传输协议FTP、域名解析服务DNS、电子邮件协议SMTP、超文本传输协议HTTP


|         | ISO/OSI参考模型                           | TCP/IP模型                               |
| ------- | ------------------------------------- | -------------------------------------- |
| 基本设计思想  | 现有模型后有协议<br>区分服务、协议和接口的概念             | 现有协议后有模型<br>在服务、协议和接口三个概念上并未做明确区分      |
| 通用性与实用性 | 通用性良好而实用性很差                           | 通用性较差而实用性很好                            |
| 提供的服务类型 | 网络层: 无连接不可靠和有连接可靠服务<br>传输层: 仅提供可靠传输服务 | 网络层: 无连接不可靠的数据报服务<br>传输层: 可靠传输和不可靠传输服务 |
| 流量控制    | 除了物理层和表示层外, 都可以提供流量控制                 | 传输层和应用层九二一提供流量控制                       |
### 五层协议的体系结构


| 应用层<br>传输单位为报文                  | 通过进程间的交互完成特定网络应用<br>HTTP、FTP、SMTP、POP3           |
| ------------------------------- | ------------------------------------------------ |
| 传输层<br>传输单位为报文(TCP)/用户数据报P(UDP) | 为进程提供通用数据传输服务<br>TCP、UDP                         |
| 网络层<br>传输单位为分组                  | 为主机提供数据传输服务, 将报文段或用户数据报封装成分组<br>IP、ICMP、IGMP、ARP |
| 数据链路层<br>传输单位为帧                 | 为同意链路的主机提供数据传输服务, 将分组封装成帧<br>PPP                 |
| 物理层<br>传输单位为比特                  | 在物理线路上传输原始的比特数据                                  |
