# 6.5.1 www的概念与组成结构

万维网(WorldWideWeb, WWW)是一个分布式、联机式的信息存储空间, 在这个空间中: 一样有用的事物称为一样资源, 并由一个全域统一资源定位符(URL)标识. 这些资源通过超文本传输协议(HTTP)传送给使用者,  而后者通过单击链接来获取资源

万维网的内核部分是由三个标准构成的:
1. 统一资源定位符(URL): 负责标识万维网上的各种文档, 并使每个文档在整个万维网的范围内具有唯一的标识符URL
2. 超文本传输协议(HTTP): 一个应用层协议, 它使用[[5.3 TCP|TCP]]连接进行可靠的传输, HTTP是万维网客户程序和服务器程序之间交互所必须严格遵守的协议
3. 超文本标记语言(HTML): 一种文档结构的标记语言, 它使用一些约定的标记对页面上的各种信息(包括文字、声音、图像、视频等)、格式进行描述

URL是对可以从因特网上得到的资源的位置和访问方法的一种简洁表示. URL相当于一个文件名在网络范围的扩展. URL的一般形式是: **<协议>://<主机>:<端口>/<路径>**
+ <协议>指用什么协议来获取万维网文档, 常见的协议有http、tp等
+ <主机>是存放资源的主机在因特网中的域名或IP地址
+ <端口>和<路径>有时可省略
在URL中不区分大小写

万维网以[[6.1 网络应用模型#6.1.1 客户/服务器模型|客户/服务器]]模式工作/ 浏览器是在用户主机上的万维网客户程序, 而万维网文档所驻留的主机则运行服务器程序, 这台主机称为万维网服务器. 客户程序向服务器程序发出请求, 服务器程序向客户程序送回客户所要的万维网文档, 工作流程如下：
1. Web用户使用浏览器(指定URL)与Web服务器建立连接, 并发送浏览请求
2. Web服务器把URL转换为文件路径, 并返回信息给Web浏览器
3. 通信完成, 关闭连接
万维网是无数个网络站点和网页的集合, 它们在一起构成了因特网最主要的部分(因特网也包括电子邮件、Usenet和新闻组)

# 6.5.2 超文本传输协议

超文本传输协议(HTTP)定义了浏览器(万维网客户进程)怎样向万维网服务器请求万维网文档, 以及服务器怎样把文档传送给浏览器. 从层次的角度看, HTTP是面向事务(Transaction-oriented)的应用层协议, 它规定了在浏览器和服务器之间的请求和响应的格式与规则, 是万维网上能够可靠地交换文件(包括文本、声音、图像等各种多媒体文件)的重要基础

## HTTP的操作过程

1. 每个万维网网点都有一个服务器进程, 它不断地监听TCP的端口80, 以便发现是否有浏览器向它发出连接建立请求
2. 一旦监听到连接建立请求并建立了TCP连接之后, 浏览器就向万维网服务器发出浏览某个页面的请求, 服务器接着就返回所请求的页面作为响应
3. 服务器在完成任务后, TCP连接就会被释放

## HTTP的特点

>[!attention] HTTP的特点
> HTTP通过面向连接的TCP协议保证了可靠传输, 但是**HTTP本身是无连接的**, 即不需要先建立HTTP连接
> **HTTP是无状态的**, 同一个客户第二次访问同一个服务器的页面时, 服务器的响应与第一次被访问时的相同

在实际应用中, 通常使用Cookie加数据库的方式来跟踪用户的活动(如记录用户最近浏览的商品等)

>[!info] Cookie的工作原理
> 1. 当用户初次浏览某个使用Cookie的网站时, 该网站服务器就为用户产生一个唯一的Cookie识别码, 如"12345", 并以此为索引在后端数据库中创建一个项目, 用来记录用户访问该网站的各种信息
> 2. 接着在给用户的响应报文中添加一个Set-cookie的首部行"Set cookie:12345"", 用户收到响应后, 就在它管理的特定Cookie文件中添加该服务器的主机名和Cookie识别码
> 3. 当用户再次浏览这个网站时, 会取出这个网站的识别码, 并在请求报文中添加一个Cookie首部行"Cookie:12345". 服务器根据Cookie识别码就能从数据库中查询到该用户的活动记录, 进而执行一些个性化的工作, 如根据用户的历史浏览记录向其推荐新商品等

**HTTP既可使用非持续连接(HTTP/1.0), 又可使用持续连接(HTTP/1.1支持)**

1. 非持续连接(close): 在非持续连接下, 客户端向服务器每请求一个Web对象(如HTML文件、图像文件等), 都需要先建立TCP连接, 再进行对象请求和传输. 在默认情况下, HTTP/1.0采用非持续连接
2. 持续连接(keep-alive): 从HTTP/1.1起默认开始使用持续连接, 在该连接下, 服务器在发送响应报文后不会立马关闭TCP连接, 相同的客户与服务器之间的多个数据可基于同一个TCP连接来传送HTTP/1.1支持流水线机制, 因此, 持续连接又可分为:
	1. 不带流水线的持续连接: 客户端在发送一个请求之后, 必须在收到服务器对该请求的响应后才能发送下一个请求(获取每一个引用到的对象都要花费1个RTT)
	2. 带流水线的持续连接: 客户端可以无需等待对前一个请求的响应, 继续发送新的请求(获取所有引用到的对象一共只花费1个RTT)
3. 非持续连接、不带流水线的持续连接和带流水线的持续连接下传输过程的对比
	客户此时想向服务器请求一个包含两个图像元素的页面index.html, 要求获取到页面对象后才能请求图像对象. 三种连接方式下完整请求到该页面所需的时间分别为:
	1. 非持续连接下(HTTP1.0)的用时: 连接建立时间×3+3个RTT+连接关闭时间x2
	2. 不带流水线的持续连接下(HTTP1.1)的用时: 连接建立时间+3个RTT
	3. 带流水线的持续连接下(HTTP1.1-Pipeline)的用时: 连接建立时间+2个RTT

## HTTP的报文结构

HTTP是面向文本的(Text-Oriented), 因此报文中的每个字段都是一些ASCI码串, 并且每个字段的长度都是不确定的. 有两类HTTP报文:
+ 请求报文: 从客户向服务器发送的请求报文
+ 响应报文: 从服务器到客户的回答

![[HTTP的报文结构.png]]

1. 开始行: 用于区分是请求报文还是响应报文: 请求行用来说明请求类型、要访问的资源以及使用的HTTP版本. 开始行的三个字段之间都以空格分隔开, 最后的"CR"和"LF"分别代表"回车"和"换行"
2. 首部行: 用于说明浏览器、服务器或报文主体的一些信息. 首部可以有好几行, 也可以不使用. 在每个首部行中都有首部字段名和它的值, 整个首部行结束时, 还有一空行将首部行和后面的实体主体分开
3. 实体主体: 实体主体可以附带请求数据或响应数据. 在请求报文中一般不用这个字段, 在响应报文中也可能没有这个字段

| 方法      | 意义                   |
| ------- | -------------------- |
| GET     | 请求读取URL所标志的信息(不改变信息) |
| HEAD    | 请求读取由URL所标志的信息的首部    |
| POST    | 给服务器增加信息(如注释)        |
| PUT     | 向服务器发送数据以更新现有资源      |
| DELET   | 删除指明的URL所标志的资源       |
| CONNECT | 用于代理服务器              |

>[!info] 状态码
> 1. 1xx表示通知信息, 如请求收到了或正在进行处理
> 2. 2xx表示成功, 如接受或知道了
> 3. 3xx表示重定向, 如要完成请求还必须进一步的行动
> 4. 4xx表示客户的差错, 如请求中有错误的语法或不能完成
> 5. 5xx表示服务器的差错, 如服务器失效无法完成请求

```
GET /bbs/index.htm HTTP/1.1 {指明方法"GET"、相对URL、HTTP版本}
Host: www.cskaoyan.com      {指明服务器的域名}
Connection: Keep-Alive      {要求服务器在发送完被请求的文档后保持这条连接}
User-Agent: Mozilla/5.0     {表明用户代理是浏览器Mozilla/5.0}
Accept-Language: cn         {表示用户希望优先得到中文版本的文档}
```

+ Host: 指明请求将要发送到的服务器的主机名和端口号，如"Host:www\.xyz.edu:8080", 若没有端口号则使用被请求服务的默认端口号
+ Cookiel: 指明Cookie识别码, 该识别码用于索引服务器生成后发送到客户端并保存在用户浏览器的数据项目. 当浏览器向某服务器发出的HTTP请求报文中包含Cookie字段时表明浏览器曾经访问过该服务器
+ Connection: 指明当前请求结束后, 是否关闭网络连接. 如果为"close"(HTTP/1.0的默认值), 表明需要关闭该网络连接; 如果为"keep-alive"(HTTP/1.1的默认值), 表明继续保持该连接, 后续请求可以继续在该连接上处理
