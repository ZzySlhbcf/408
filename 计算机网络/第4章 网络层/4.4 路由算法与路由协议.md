# 4.4.1 路由算法

路由算法是用来找到从源主机到目的主机的最佳路径(代价/花费最小的路径)的算法, 主要分为静态路由算法和动态路由算法两大类

![[三种路由协议的比较.png]]
## 静态路由与动态路由

1. 静态路由算法: 又称非自适应路由算法, 由网络管理员手工配置路由表项, 当网络拓扑或链路状态发生变化时吗需要人为修改路由表
	静态路由的特点是简单和开销较小, 但不能及时适应网络状态的变化, 适用于较简单的小网络
2. 动态路由算法: 又称自适应路由算法, 根据路由器互相交换的信息建立路由表, 不同动态路由算法信息交换时机不同, 但总能及时应对网络变化并作出必要修改
	动态路由的特点是能较好地适应网络状态的变化, 但实现起来较为复杂, 开销也比较大, 适用于较复杂的大网络

典型的动态路由算法有距离一向量路由算法和链路状态路由算法
## 距离-向量路由算法

Bellman-Ford算法是一种用于计算单源最短路径的算法, 该算法的关键是根据Bellman-Ford方程来更新节点的最短路径估计值
设$d_x(y)$是从x到y的最小代价路径的代价值, 则有如下转移方程:
$d_x(y)=\min\{c(x,v)+d_v(y)\}$, 其中v为x的任意邻居, c(x,v)为v到x的代价

>[!note] 两点之间的最短路径也包含了路径上其他顶点的最短路径

![[Bellman-Ford算法的基本思想.png]]

距离一向量算法是一种用于计算网络路由的分布式算法, 它是一种基于Bellman-Ford算法的路由算法, 主要具有如下的5条特性
1. 距离通常体现为跳数
2. 距离-向量路由选择依赖邻居的路由信息计算最短距离, 网络中所有路由器都参与距离向量(DV)的交换
3. 每当路由器从邻居节点接收到信息, 就需要与自身路由表进行对比更新
4. 路由器定期向所有的邻居发送完整路由表
5. 每条路由表项至少包含三个信息: 目的网络、代价、下一跳

![[距离向量算法实现的举例.png]]

更新报文的大小与网络中的节点数量成正比, 大型网络将导致很大的更新报文
## 链路状态路由算法

链路状态算法是一种用于计算路由表的网络路由算法, 它基于Dijkstra算法计算源节点到其他节点的最短路径, 主要具有5条特性
1. 全局拓扑结构通过汇集节点邻接关系形成
2. 链路状态算法中, 节点交换的路由信息称为链路状态分组(LSP), 其中包含节点标识、链路列表、序号等信息
3. 路由信息的交换通过洪泛方式进行, 路由器准备好链路状态分组后将发向其他所有节点
4. 路由信息的交换时机有两种
5. 每个路由器接收到洪泛而来的链路状态分组之后, 逐步建立网络拓扑信息、生成最短路径树，并据此构建路由表

# 4.4.2 分层次的路由选择协议

> + 层次路由: 是一种路由策略, 它采用分治办法将超大规模网络划分为多个较小区域. 多个局域网构成一个区域, 区域内通过一般的路由算法实现区域内路由选择, 每个区域都是一个自治系统
> + 自治系统(AS): 是在单一技术管理下的许多网络、IP地址以及路由器, 这些路由器使用一种自治系统内部的路由选择协议和共同的度量

将互联网划分成多个AS后, 把路由选择协议划分为两大类:
1. 内部网关协议/域内路由选择协议(IGP): IGP协议工作于自治系统内部, 每个自治系统可以使用不同的IGP协议. 典型的IGP协议有RIP和OSPF
2. 外部网关协议/域间路由选择协议(EGP): 各自治系统间需要使用统一的EGP协议. 典型的EGP协议有BGP

每个自治系统自己决定在本自治系统内部运行哪一个内部路由选择协议. 另外, 每个自治系统都有一个或多个路由器除运行本系统的内部路由选择协议外, 还要运行自治系统间的路由选择协议, 例如R1、R2

# 4.4.3 路由信息协议

路由信息协议(RIP)是一种分布式的基于距离一向量的路由选择协议

1. **距离度量标准为跳数**, 路由器到直连网络的跳数规定为1, 跳数最大值为15, 跳数16代表距离"无穷大". 到非直连网络时, 每经过一个路由器跳数就加一
2. **路由信息的交换对象为相邻路由器, 交换的信息为完整路由表**, 路由表中的每个表项都有三个关键字段: <目的网络N,距离d,下一跳路由器地址X>
3. **按固定的时间间隔(如30s)交换路由信息**, 然后路由器根据收到的路由信息更新路由表. 当网络拓扑发生变化时, 路由器也及时向相邻路由器通告拓扑变化后的路由信息
4. 路由表项具有老化时间. 若长期(如180s)未收到与某一路由表项的相关信息, 则将该表项标记为无效
5. RIP工作于**应用层**, 基于[[5.2 UDP|UDP]]协议封装报文, 所用端口号为520

1. 第一步是初始化: RIP路由器会初始化它的路由表, 为与自己直连的网络创建表项, 并将距离设置为1，下一跳设置为空值
2. 第二步是基于距离一向量算法进行周期性更新: RIP路由器完成初始化后会定期与自己的邻居交换完整的路由表, 用收到的邻居路由表来更新自己的路由表. 经过多次这样的更新操作后, RIP路由器最终会进入收敛态

![[RIP更新示例.png]]

>[!note] RIP的优点与缺点
> 1. 优点
>	+ RIP协议实现简单、开销小
>	+ 若一个路由器发现了更短的路由, 则这种更新信息就传播得很快, 在较短时间内便可被传至所有路由器, 俗称"好消息传播得快"
>2. 缺点
>	+ RIP协议适用的网络规模较小, 最大一般不能超过15跳
>	+ 路由器之间交换的是路由器中的完整路由表, 因此网络规模越大, 开销也越大
>	+ 当网络出现故障时, 路由器之间需反复多次交换信息才能完成收敛, 要经过较长时间才能将故障消息传送到所有路由器(即慢收敛现象), 俗称"坏消息传播得慢"

# 4.4.4 开放最短路径优先协议

## 开放最短路径优先OSPF的基本特点

1. OSPF路由器的链路状态包括: 本路由器和哪些路由器相邻; 到这些路由器的链路代价
2. 链路代价的决定因素丰富灵活且具有动态性, 代价具体参考的因素有距离、带宽、延迟等
3. OSPF协议工作于网络层, **是网络层协议, 不使用UDP或TCP**, 它将数据封装至IP分组中, 通过IP分组进行传输，相应的IPv4首部协议字段值为89
## OSPF的基本工作原理

1. 使用洪泛法向本自治系统中所有路由器发送信息. 具体来说, 路由器通过所有输出端口向所有相邻的路由器发送信息. 每一个相邻路由器收到后, 再将此信息发往刚刚发来信息的路由器以外的所有相邻路由器. 最终, 整个区域中所有的路由器都得到了这个信息
2. 当链路状态发生变化或每隔一段时间(如30分钟), 路由器向所有路由器用洪泛法发送链路状态信息
3. 由于各路由器之间频繁地交换链路状态信息, 所有的路由器最终都能建立一个链路状态数据库, 这个数据库实际上就是全网的拓扑结构图, 全网范围内是一致的, 也被称为链路状态数据库的同步
4. 每一个路由器使用链路状态数据库中的数据, 构造出自己的路由表(例如, 使用Djikstra的最短路径算法)

OSPF的链路状态数据库能较快地进行更新, 使各个路由器能及时更新其路由表, 收敛快

为了使OSPF能够用于规模很大的网络, OSPF将一个自治系统再划分为若干更小的范围, 称为区域

![[OSPF划分区域举例.png]]

1. 每一个区域都有一个32位的区域标识符, 用点分十进制形式表示(如0.0.0.1)
2. 在一个区域内部的路由器只知道本区域的完整网络拓扑, 而不知道其他区域的网络拓扑的情况
3. 为了使每一个区域能够和本区域以外的区域进行通信, OSPF使用层次结构的区域划分. 在上层的区域叫作主干区域, 其标识符规定为0.0.0.0
4. 主干区域的作用是用来连通其他在下层的区域. 从其他区域来的信息都由区域边界路由器进行概括, 每一个区域至少应当有一个区域边界路由器(如R3、R4和R7)
5. 在主干区域内的路由器叫作主干路由器(如R3): 一个主干路由器可以同时是区域边界路由器(如R3)
6. 在主干区域内还要有一个路由器专门和本自治系统外的其他自治系统交换路由信息, 即自治系统边界路由器(如R6)

划分区域的好处是把洪泛法交换链路状态信息的范围局限于每一个区域而不是整个的自治系统, 有效减少了整个网络上的通信量但同时, 采用分层次划分区域的方法增加了交换信息的种类, 使OSPF协议变得更加复杂
## OSPF的分组类型

1. 问候分组(HELLO): 用来发现和维持邻站的可达性
2. 数据库描述分组(DBD): 向邻站给出自己的链路状态数据库中的所有链路状态项目的摘要信息
3. 链路状态请求分组(LSR): 向对方请求发送某些链路状态项目的详细信息
4. 链路状态更新分组(LSU): 用洪泛法对全网更新链路状态, 它是OSPF最核心的部分
5. 链路状态确认分组(LSACK): 对链路状态更新分组的确认


1. 每一个OSPF路由器用数据库描述分组和相邻路由器交换本数据库中已有的链路状态摘要信息, 摘要信息主要指出有哪些路由器的链路状态信息已经写入了数据库
2. 经过与相邻路由器交换数据库描述分组后, 路由器使用链路状态请求分组, 向对方请求发送自己所缺少的某些链路状态项目的详细信息. 通过一系列的这种分组交换, 全网同步的链路数据库就建立了

注意:
1. 在网络运行的过程中, 只要一个路由器的链路状态发生变化, 该路由器就要使用链路状态更新分组, 用可靠的洪泛法向全网更新链路状态
2. 两个相邻路由器每隔10秒钟要交换一次问候分组. 确知哪些邻站是可达的
3. 若有40秒钟没有收到某个相邻路由器发来的问候分组, 则认为该相邻路由器是不可达的, 应立即修改链路状态数据库, 并重新计算路由表
# 4.4.5 边界网关协议

## BGP的基本特点

> 边界网关协议(BGP): 是基于路径一向量路由算法的外部网关协议. 目前常用的是BGP版本4

1. 路由信息交换对象是"BGP发言人": 发言人通常是**自治系统边界路由器**. BGP协议支持两种会话:
	1. 内部BGP(I-BGP)会话: 发生在同一自治系统内的两个**相邻设备**之间的BGP会话
	2. 外部BGP(E-BGP)会话: 发生在不同自治系统的两个BGP邻居之间的BGP会话
2. 发言人间交换的是**网络可达性信息**: 可达性信息包括自治系统内部所有网络, 以及通过该自治系统可到达的其他网络的信息(附带路径向量)
3. BGP协议**可规避路由环路问题**: BGP发言人收到可达性信息后, 检查到达目的网络的路径中是否存在环路, 若存在环路则忽略这些信息
4. BGP协议工作于应用层, 基于[[5.3 TCP|TCP]]协议封装报文, 所用端口号为179

## BGP路由

BGP路由的一般格式为: **BGP路由=<CIDR前缀，BGP属性>**
当一个路由器通过BGP会话向对等方通告一条BGP路由时, 最重要的两个BGP属性是AS-PATH(自治系统路径)和NEXT-HOP(下一跳)

+ AS-PATH: 是通告的BGP路由所经过的自治系统
	在BGP中, 通常用一个全局唯一的自治系统号(ASN)来标识自治系统, BGP路由每经过一个AS, 就将其ASN加入AS-PATH
	BGP路由必须指出通过哪些AS, 但不指出路由要通过哪些路由器
+ NEXT-HOP: 是通告的BGP路由起点

AS2中的R4收到一条BGP路由"X,AS1,R1", 表示"从RI出发能到达AS1中的网络X, 即RI->X", R4为了构造自己的转发表, 需要对这条BGP路由的起点进行转换. 电于路由的起点R1并不在AS2中, AS2中的路由器都不能识别R1, 因此R4先把路由的起点添加上R1的对等方R2, 这样就变为"R2->R1->X"
R2在AS2中, 因此AS2中的所有路由器都能把分组转发到R2, 再经过R1, 最终到达X
然后, R4利用内部网关协议, 找到从R4到R2的最佳路由中的下一跳. 查出下一跳是R3, 于是R4在转发表中增加到达网络X的下一跳是R3的表项<X,R3>. 这样, R4只要收到目的网络为X的分组, 就都按照路径R4->R3->R2->R1->X, 最后到达X. 类似地, R3也在自己的转发表中增加到达网络X的表项<X,R2>. 每个路由器收到一条新的BGP路由通告后, 必须经过上述步骤，才能在自己的转发表中增加到达X的"下一跳"的相应表目

![[BGP路由的起点经过的AS和终点.png]]


1. 配置BGP时, 每个自治系统(AS)的管理员要选择至少一个路由器, 作为该AS的"BGP发言人"
2. 一个BGP发言人与其他AS中的BGP发言人进行通信时，必须先建立TCP连接, 这种TCP连接又称为半永久性连接, 即双方交换完信息后仍然保持着连接状态
3. 每个BGP发言人除了必须运行BGP外, 还必须运行该AS所用的内部网关协议
4. 当BGP发言人互相交换网络可达性信息后, 各BGP发言人就根据所用的策略, 从收到的路由信息中找出到达各自治系统的较好路由而非最佳路由

## BGP路由选择

若从一个AS到另一个AS中的网络X只有一条BGP路由, 则不存在选择BGP路由的问题, 此时BGP路由是唯一的
然而, 若到网络X有两条或更多的BGP路由可供选择, 则应根据下列原则, 并按下面给出的先后顺序, 选择一条较好的BGP路由

1. 首先选择本地偏好值最高的路由: 在BGP路由的属性中有一个称为本地偏好的选项, 一条路由的本地偏好可能由该路由器管理员设置, 也可能是从同一AS中的另一个路由器学习得到的
	若在几条BGP路由中找不出本地偏好值最高的路由(如它们的本地偏好值都相同), 则采用下面的方法
2. 选择AS跳数最少(AS-PATH最短)的路由: 假设从AS1到AS5共有两条BGP路由, 根据该原则, 应选择只通过1个AS的BGP路由, 即AS1→AS4→AS5
	然而, 由于AS4是个很大的AS, 分组在AS4中反而要经过更多次数的转发, 可能要花费更长的时间
	**可见, AS跳数最少的路由未必是最好的**
3. 3）使用热土豆路由选择算法: 选择最靠近NEXT-HOP路由器的路由, 让分组经过最少的转发次数离开本AS, 这时要使用内部网关协议(如OSPF或RIP), 对不同的路由器, 得出的选择结果是不同的
4. 选择BGP标识符的数值最小的路由: 在BGP报文的首部有一个称为BGP标识符的字段, 该字段作为运行BGP的路由器的唯一标识符

## BGP的四种报文

1. 打开(Open)报文: 用来与相邻的另一个BGP发言人建立关系
2. 更新(Update)报文: 用来通知某一路由的信息, 以及列出要撤销的路由
3. 保活(Keepalive)报文: 用来周期性地证实与邻站/邻居的连通性
4. 通知(Notification)报文: 用来发送检测到的差错

若一个BGP发言人想与另一个AS的BGP发言人建立邻站关系, 则要向对方发送Open报文, 若对方接受这种邻站关系, 则用Keepalive报文响应
邻站关系一旦建立, 就要继续维持这种关系. 为此, 这两个BGP发言人彼此要周期性地交换Keepalive报文(一般每隔30s)
Update报文是BGP的核心内容, BGP发言人可以用Update报文撤销它曾经通知过的路由, 也可以宣布增加新的路由
